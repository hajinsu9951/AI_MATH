이미지는 행렬이다 — 표현과 변환

사진 한 장을 크게 확대하면 작은 네모 칸들이 보입니다. 칸마다 0부터 255까지의 수가 하나씩 들어 있고, 그 수들을 가로·세로로 늘어놓은 것이 곧 행렬입니다. 오늘은 사진을 행렬로 적어 보고, 그 행렬에 수를 더하거나 곱해서 사진을 바꿔 봅니다.

오늘의 학습 목표
① 이미지의 각 픽셀 위치와 밝기 값을 행렬의 성분으로 나타내고, 해상도와 성분의 개수를 계산할 수 있습니다. [12인수03-01]
② 검은색 0·흰색 1의 이진행렬과 0~255의 회색조 행렬을 구분하여 이미지를 표현할 수 있습니다. [12인수03-01]
③ 행렬의 덧셈 A + tJ 와 실수배 kA 로 밝기를, 뺄셈 255J − A 로 반전을 만들고 클리핑을 설명할 수 있습니다. [12인수03-02]
④ 두 이미지의 합성 C = αA + (1 − α)B 가 수직선 위 내분점과 같은 식임을 설명할 수 있습니다. [12인수03-02]

단계 2 · 정리 — 행, 열, 성분, 그리고 m × n 행렬

수를 직사각형 모양으로 늘어놓고 괄호로 묶은 것을 행렬이라 하고, 그 안의 수 하나하나를 성분이라고 합니다. 가로줄이 행, 세로줄이 열이며, 행이 m개·열이 n개이면 m × n 행렬이라고 합니다.

단계 3 · 정의 확인 — 이진행렬이란 무엇인가

정의. 검은색을 0, 흰색을 1 로 하여 이미지를 나타낸 행렬을 이진행렬이라 합니다. 이미지의 제 i 줄 제 j 칸은 행렬의 (i, j) 성분에 대응하므로, 위치 정보가 그대로 보존됩니다.

단계 1 · 관찰 — 해상도를 낮추면 무엇이 먼저 사라지나

4 × 4로 낮추면 “7”이라고 알아보기 어려워집니다. 픽셀 한 칸이 넓은 영역의 평균 밝기를 대표하게 되어 가는 획과 모서리 같은 작은 특징이 먼저 사라지기 때문입니다.

단계 수를 2 → 256으로 올리면 획의 가장자리가 부드러워집니다. 2단계에서는 획의 경계가 톱니처럼 끊기지만 256단계에서는 중간 회색이 그 사이를 메웁니다.

해상도를 가로·세로 모두 2배로 늘리면 픽셀 수는 4배가 됩니다. 저장 용량과 계산량도 함께 늘어납니다. 이 맞바꿈이 곧 “적당한 해상도”를 고르는 이유입니다.

단계 2 · 정리 — 왜 하필 256단계인가

검은색과 흰색 사이의 회색 영역을 256단계로 나누어 0부터 255까지의 값으로 표현한 것이 그레이 스케일(회색조)입니다. 값이 클수록 밝습니다.

왜 256일까요? 컴퓨터는 정보를 0과 1로 저장하고, 8비트로 28 = 256가지를 나타낼 수 있기 때문입니다. 8비트는 정확히 1바이트여서 저장에도 효율적입니다.

1바이트 = 8비트 · 28 = 256단계 · 1KB = 1024바이트 · 1MB = 1024KB

단계 2 · 정리 — 255를 넘으면 컴퓨터는 어떻게 할까

8비트 회색조에서 한 칸이 가질 수 있는 값은 0 이상 255 이하의 정수뿐입니다. 계산 결과가 이 범위를 벗어나면 범위 안으로 잘라 넣습니다. 이것을 클리핑이라고 합니다.

  • 0보다 작아지면 → 0 (검은색보다 더 검은 색은 없습니다)
  • 255보다 커지면 → 255 (흰색보다 더 흰 색은 없습니다)

되돌릴 수 없다는 점이 중요합니다. 255로 잘린 칸들은 원래 280이었는지 460이었는지 알 수 없게 되어, k를 다시 0.5로 낮춰도 원본으로 돌아오지 않습니다. 직접 확인해 보세요 — 미션 ④(2배)를 누른 뒤 [클리핑 0~255] 체크를 끄면 값 패널에 붉은 수가 나타납니다.

단계 3 · 정의 확인 — 밝기 변환 A + tJ 와 대비 변환 kA

같은 꼴의 두 행렬 A = (aij), B = (bij) 에 대하여 A ± B 의 (i, j) 성분은 aij ± bij 이고, kA 의 (i, j) 성분은 k · aij 입니다.

모든 성분이 1인 행렬을 J 라 할 때, 이미지 행렬 A 에 대하여

밝기 변환 A + tJ (t > 0 밝게 · t < 0 어둡게)
대비 변환 kA (k > 1 또렷하게 · 0 < k < 1 흐리게)

결과가 0 미만이면 0으로, 255 초과이면 255로 잘라 넣습니다(클리핑). 성분이 정수가 아니면 반올림·올림·버림으로 정수로 맞춥니다.

사진 앱의 ‘밝기’ 버튼이 덧셈, ‘대비’ 버튼이 실수배에 해당합니다.

단계 1 · 관찰 — 반전을 두 번 하면? 계수의 합은 왜 언제나 1인가

반전을 두 번 하면 원본으로 돌아옵니다. 255 − (255 − a) = a 이기 때문입니다. 클리핑과 달리 반전은 정보를 잃지 않는 변환입니다.

표를 보면 A의 계수 + B의 계수 = 1 이 한 번도 깨지지 않습니다. 합이 1보다 크면 사진이 전체적으로 밝아지고(흰색 쪽으로 몰림), 1보다 작으면 어두워집니다.

합을 1로 묶어 두었기 때문에 ‘섞임’만 일어나고 밝기는 유지됩니다. 그래서 α 하나만 정하면 나머지는 자동으로 1 − α 로 정해집니다.

단계 2 · 정리 — 수직선의 내분점과 사진 합성은 같은 식

수직선 위의 두 점 A(a), B(b)에 대하여 선분 AB를 m : n 으로 내분하는 점 P의 좌표는

P = (m·b + n·a) ÷ (m + n) = (n/(m+n))·a + (m/(m+n))·b

여기서 α = n/(m+n) 이라 하면 P = αa + (1 − α)b 이고, 두 계수의 합은 언제나 1입니다.

사진 합성은 이 계산을 모든 픽셀에서 한꺼번에 하는 것입니다. 수 하나가 행렬 하나로 바뀌었을 뿐, 식의 모양은 완전히 같습니다.

C = αA + (1 − α)B (0 ≤ α ≤ 1)

단계 3 · 정의 확인 — 반전과 합성

색상 반전. 성분이 모두 255인 행렬을 255J 라 할 때 반전된 이미지는 A′ = 255J − A 입니다. 한 칸만 보면 y = 255 − x, 즉 기울기가 −1인 일차함수입니다.

합성. 0 ≤ α ≤ 1 인 실수 α 에 대하여 C = αA + (1 − α)B 입니다. 두 계수의 합은 언제나 1이며, α 가 1에 가까울수록 A가, 0에 가까울수록 B가 선명합니다.

α 를 1에서 0까지 천천히 바꾸면 A 위로 B가 겹치며 넘어가는 오버랩이 됩니다. 영화에서 한 장면이 흐려지며 다음 장면이 또렷해지는 전환이 바로 이 식입니다.

STEP 3 · 정리 (8분)

오늘의 핵심 3줄

  1. 이미지는 픽셀의 밝기 값을 성분으로 하는 행렬입니다. 이진행렬은 0·1 두 값, 회색조는 0~255 256단계를 씁니다. 필요한 수의 개수는 해상도로 정해집니다.
  2. 밝기는 A + tJ, 대비는 kA, 반전은 255J − A 입니다. 결과가 0~255를 벗어나면 잘라 넣고(클리핑), 잘린 값은 되돌릴 수 없습니다.
  3. 두 이미지의 합성 C = αA + (1 − α)B 는 수직선 위 내분점과 같은 식이며, 두 계수의 합은 언제나 1입니다.

사진은 픽셀 값을 성분으로 갖는 행렬이므로, 필터는 그 행렬의 모든 성분에 한꺼번에 같은 계산을 적용하는 것입니다. 같은 수를 더하거나(A + tJ), 곱하거나(kA), 255에서 빼는(255J − A) 것입니다.

① 사진첩에서 사진 한 장을 고르고 해상도를 확인합니다(스마트폰: 사진 → 정보 / PC: 파일 속성 → 자세히). 회색조로 저장할 때 필요한 수의 개수를 계산합니다.
